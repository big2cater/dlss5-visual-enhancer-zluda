DLSSNRFilter ZLUDA 加速与双引擎多轮降噪发布包 (2026-09-14)

【使用方法】
1. 解压整个文件夹，不要只复制单个 DLL。
2. 将 NVIDIA 官方的 nvngx_dlssnr.dll 放入根目录（与 video_filter.exe / dlssnr_gui.exe 同级目录）。
3. 双击运行 dlssnr_gui.exe（Qt 6 统一现代图形界面；视频批处理与单图增强都在这个窗口里）。
4. 视频处理需要 ffmpeg.exe 和 ffprobe.exe；请确保已安装 FFmpeg 并把 bin 目录加入系统环境变量 PATH。
5. 首次使用请先点击 GUI 中的【预热缓存】按钮预热翻译缓存（进度实时显示在日志窗口，约 20~40 分钟，仅此一次）；
   完成后状态栏显示"缓存已就绪"，即可秒级处理图片/视频。更换程序版本或更换显卡后需要重新预热一次（自动检测）。
   直接跳过预热也能处理，但首次会长时间无进度提示，容易误以为卡死。

【本次修复 (v2026.09.14-v4)】
1. 单图路径的"明亮门槛"上调（承接 v3）：
   - v3 把单图判定门槛定为线性 0.25，实测发现余量太小：在暴露问题的那一帧上（预告片首个暗帧，
     峰值 0.239）门槛只高出 **4.8%** —— 那不是余量，是巧合。
   - 现提高到线性 **0.35**（sRGB ≈159/255），同一帧余量变为 **47%**；处理器内部同款判定一并同步，
     两处数值保持相等（代码注释里互相注明来源）。
   - 影响：更暗的静帧不会被判为"竞态"（宁可漏报也不误杀）；亮度足够高、却输出全黑的静帧仍会被判出。

【本次修复 (v2026.09.14-v3)】
1. 补齐"空白判定"的同类遗漏（承接 v2）：
   - v2 只修正了视频"处理阶段"的那一处判定；复查后发现**还有三处**同类判据仍在用旧门槛：
     编码阶段的判定、单图路径的判定、以及处理器内部的两道判定（process / process_raw_rgb48）。
   - 现在统一为：视频侧要求"输入明显明亮（>sRGB ≈93/255）+ 连续 3 帧"才判竞态；
     单图侧只有一帧、无法用连续帧区分，改用更高的明亮门槛（线性 0.25 ≈ sRGB 138/255），
     并把判定结果与实测输入峰值一并打进日志，事后可复核；
     处理器内部那道**看不到输入亮度**的检查收窄为只判"全零"（真正的发射失败指纹），
     近零但非零的情况交回给有上下文的判定。
   - 另：视频"处理阶段"的检查不再只覆盖前 ~2 秒，而是**逐帧**生效 —— 开场很暗的片段、
     或较晚才出现的竞态，现在也能被发现。
   - 实测：预告片 120 帧 exit 0 / blanks=0；回归片段 exit 0 / ~106 ms/帧 / blanks=0；
     暗帧单图 exit 0（日志："输入峰值 12517/65535，门槛 13312 ⇒ 未判定为空白"）；
     视频两处门的触发路径分别用临时强制构建验证（连续两帧告警、第三帧中止、退出码 2、blanks=1）。

【本次修复 (v2026.09.14-v2)】
1. 修复"淡入黑场片头被误判为竞态、导致整部影片永远无法处理"的问题：
   - 现象：影片开场是黑场（预告片、片头黑幕等，约 0.2~0.3 秒）时，处理会反复报
     "输出空白而输入有内容（ZLUDA 竞态），交由外层重跑"，以全新进程重试多次，
     但每次都在**同一个帧**失败，最终只能中止 —— 整部影片无法开始处理。
   - 原因：空白判定原先只要求"输入有信号"（任一通道 > sRGB 27/255）。淡入时第一帧刚越过
     这条线，而该帧本身仍接近纯黑、网络的历史缓冲也还是黑的，输出自然低于空白阈值，
     于是守卫把**正常画面**判成了启动竞态。
   - 修复：现在要求输入**明显明亮**（> sRGB ≈93/255，约为空白阈值的 22 倍）且**连续 3 帧**
     都满足，才判定为竞态 —— 真竞态会让每一帧都变黑，而淡入、暗场、历史重置一两帧内即恢复。
     命中时日志会同时打印"输入峰值/65535"，便于事后复核。
   - 实测：此前必然失败的淡入片头片段现已正常跑完；常规片段表现不变（640×360 稳定 ~106 ms/帧、
     无空白告警、退出码 0）。启动竞态本身仍会被正常捕获（已用强制空白构建验证：连续两帧告警、
     第三帧中止、退出码 2）。

【本次更新 (v2026.09.14-v1)】
1. MMA 配对融合正式生效（RX 7000 系 / gfx11 路径，随本包更新的 nvcuda.dll）：
   - 让编译器在 kernel 内部看到并配对相邻的 mma.sync：4 条 intrinsic 融合为 2 条 WMMA，
     A 操作数共享，零填充造成的算力浪费从 50% 降到 0；
   - 关键在于 fp8 展宽脚手架保持在调用之外，不再随每次调用重复展开 ——
     此前"配对必须靠内联、而内联本身更贵"的死结，正是被这一点解开的。
   - RX 7900 XT / 640×360 实测（同一段视频、同一片段、仅替换驱动，两轮换序复测）：
     单帧 87 ms → 67 ms（约 −23%），平均 GPU 127 ms → 106 ms，吞吐 7.33 → 8.48 fps；
     30 帧输出与改动前逐字节一致（PNG SHA-256 全部相同），画质无任何变化。
   - 同一段视频 1080p 复测：265 ms → 241 ms（约 −9%）—— 两种分辨率下的绝对节省都稳定在
     20~24 ms/帧，说明这份收益来自每个 kernel 的固定开销；分辨率越高、固定开销占比越小，
     百分比随之下降。帧时间越长观感收益越不显眼，但方向一致、绝不变慢。
   - 注意：驱动已更新，模块缓存键随之改变，首次运行或预热会重建缓存（见【使用方法】第 5 条）。

【本次核心更新】
1. 彻底解决“蒙一层灰雾/画面变黑”画质缺陷（物理级双程色彩空间转换）：
   - 全面引入 IEC 61966-2-1 标准 sRGB 与 Linear 物理辐射度（radiance）双程精确转换。
   - 输入端将 sRGB 像素精确解算为线性光强，DLSS-NR 网络在正确的物理量级上执行 HDR 局部色调映射与双边保边滤波，黑场完全回归纯黑，暗部不再被错误提亮为灰雾；
   - 输出端精确映射回标准 sRGB 编码，消除高光欠曝压暗与死黑。
   - 输出伽马值默认回归 1.0 物理标准值（1:1 直通）。
2. 解耦 Backbuffer 与 Output 别名回环（Factor 1 修复）：
   - 彻底解除 Backbuffer 与 Output 共用同一纹理的底层指针别名。
   - 为 Backbuffer 独立建立并维护原始帧副本，杜绝多轮（Multipass）评估时网络将前一轮输出作为参考物引发的递归模糊与劣化。
3. 引导纹理精准按需传入（Factor 2 修复）：
   - 针对无深度/无运动矢量的单图与标准视频场景，安全传导真实状态，避免无意义的全零深度纹理使双边滤波退化为全图均匀模糊。
4. 双引擎独立时序级联多轮降噪（Multipass）：
   - 借鉴并整合 OptiScaler-DLSSNR-PreSR-Multipass 架构，彻底重构多轮降噪管线。
   - 废除在单个 Feature 上多轮累加的旧做法，升级为双独立 Feature 级联乒乓引擎（Feature 0 -> intermediate -> Feature 1 -> result），各引擎每帧严格只推进一次时序历史，100% 消除频闪！
5. 皮肤结构保护（Skin Structure / 防塑料感保护）：
   - 完整开放底层 DLSSNR.SkinStructureStrength 参数调节（0.00 ~ 1.00），智能保留原生毛孔细节与真实皮肤微结构。
6. 单帧定帧极速对比（Frame Hold Compare）：
   - GUI 新增【单帧定帧对比】按钮，快速抽取单帧并执行高精度降噪渲染，自动弹出可拖拽中轴线的分屏对比视窗。
7. 异步流水线与 AMF 原生硬件视频编码：
   - 保持三级解耦异步流水线，支持 AMD AMF H.264 / AMF HEVC 硬件编码。
8. 视频输入管道直接映射显存零拷贝与 GPU Compute 着色器硬件格式转换：
   - 视频管道直接刷入 GPU 映射上传内存（D3D12_HEAP_TYPE_UPLOAD），彻底消除 CPU 端内存分配与多线程 LUT 查表开销；
   - 专用 HLSL 计算着色器在 GPU 端完成 RGB48 硬件对齐解包与标准 IEC 61966-2-1 线性转换（<0.05 ms），大幅降低 CPU 负载并提升吞吐。
9. 全链路防驱动崩溃与防 TDR 超时让出机制：
   - 多轮（Multipass）轮次间与视频帧间主动引入毫秒级调度让出（yield_ms，支持命令行 --yield-ms），给 Windows 桌面合成器（DWM）与显卡驱动心跳保留调度窗口，彻底终结大分辨率/多轮次下的驱动超时崩溃（LiveKernelEvent 0x141）；
   - D3D12 命令队列加入 10 秒超时安全检测与 GetDeviceRemovedReason 状态捕获，杜绝死锁；
   - 附带一键式 fix_tdr.bat 工具，为 Windows 环境一键优化 TdrDelay = 10s 运行环境。
10. RDNA 4 硬件矩阵加速重大修复（RX 9070 / gfx12 提速 20~30 倍）：
   - 彻底修复 ZLUDA 底层嵌入字节码（zluda_ptx_impl.bc）限制判断只支持 RDNA 3 的缺陷；
   - 原生激活 RDNA 4 硬件 WMMA 矩阵加速核心，彻底消除标量模拟导致的极高延迟与卡顿，单帧推理降至 40~60ms。
11. 视频全音频格式兼容增强（wmapro / wma / pcm 自动转码）：
   - 自动探测视频输入源音频编码，对于 MP4 不支持的音频流（如 wmapro、wmav2、pcm 等）自动安全转码至 AAC 192k，杜绝封装失败报错。
12. 人物肤色中性还原与暗部防色块合成：
   - 默认启用肤色自适应保护遮罩与中性色调风格，输出严格标定 Rec.709 色彩矩阵，解决皮肤发黄与暗部色块问题。
13. 灵动动作跟踪与运动矢量尺度修正：
   - 校准光流运动矢量尺度与法向范围（0.5x），大幅降低视频动态滤镜延迟，镜头快速移动时不丢人脸、不拖影。
14. 智能硬件预算守护与切片多进程并行加速（--parallel auto / 2）：
   - 针对长视频渲染耗时痛点，重构并引入时序重叠切片并行处理架构，实现双进程并发推理，视频转换耗时减半（提速近 2 倍）；
   - 独创时序预热（Warmup Overlap 30帧）接缝平滑技术：切片边界无缝衔接，彻底根除视频拼接闪烁与跳帧，处理完成后由 FFmpeg 原生秒级零损耗合并音视频流；
   - 动态硬件资源预算守护（HardwareBudget Guardrail）：自动检测 GPU 显存容量与空闲量、系统可用物理内存（RAM）及 CPU 物理/逻辑核心数。显存不足 8GB 或可用物理内存不足时自动安全回退单进程，严格限制后台编码线程并设置进程低优先级（BELOW_NORMAL_PRIORITY_CLASS），杜绝爆显存崩溃或 CPU 100% 占满导致电脑卡死/死机；
   - 全面弃用并移除老旧 C# WinForms 界面，统一拥抱轻量现代的 Qt 6 界面（dlssnr_gui.exe），原生提供【🚀 并行加速】下拉选择。

【本次修复 (v2026.09.13-v2)】
1. 运动矢量（光流）真正落实 CPU 回退：
   - 修复 GPU 光流不可用、或单次计算失败时"静默输出全零运动矢量"的问题。过去此时日志仍写着
     "using CPU fallback"，但实际没有任何回退，整段视频的时序引导都会失效；现在会真正接到
     CPU 块匹配估计器（并按需只提示一次）。
2. 预热缓存（预编译）链路加固：
   - 修复看门狗误杀：内存紧张时编译子进程会被换页、CPU 时间长时间不增长，过去会被判为"挂死"
     并计入失败；现在停滞判定窗口放宽，且在系统可用内存偏低时再翻倍。
   - 修复临时文件残留：被终止的子进程尚未真正退出就删除其 module 文件会失败，%TEMP% 下会留下
     残留模块文件；现在先回收进程再清理，并带一次重试。
3. --max-frames 与 --parallel 组合的帧预算修复：
   - 探测不到帧率（如 0/0）时，首个分片不再退化为"不限帧"跑完整个半段，预算改为按半段时长比例分配；
   - 帧预算在分片点之前就耗尽时，第二个分片改为产出 1 帧（此前会是 0 帧空分片，导致最终合并失败）。
4. GUI：ffprobe 探测超时后会被正确结束，不再残留子进程并触发 Qt 析构警告。
5. 其他健壮性与一致性修复：
   - GPU 适配器枚举增加空指针防护（DXGI 返回非 NOT_FOUND 失败码时不再可能导致崩溃）；
   - process_raw_rgb48 补齐级联多轮（Multipass）的尺寸守卫，与 process() 行为一致并给出降级提示；
   - 修正命令行退出码说明（2 表示"可重试的空白竞态"）、移除只写不读的计数、修复 --retry-delay 的
     整型溢出、--retries 仅在参数边界匹配（输出路径中同名子串不再被误改）、每帧平均耗时改用正确分母；
   - 补充说明：--upscale-mode 在视频模式下由编码器完成放大，网络仍按解码尺寸渲染。
